# Ecigmania Frontend Instructions

Before implementing any UI, read:

design/design-system.md

All frontend UI must follow the Ecigmania Design System.

Do not invent a new visual style for individual pages.

Reuse existing components whenever possible.

Prefer shadcn/ui components over custom components when
the required component already exists.

Do not introduce new colors, typography, border radii,
shadows, or spacing values without a strong reason.

When a new UI pattern is introduced, make it reusable.

Customer-facing pages and admin pages should feel like
the same product family.

Before considering a page complete, review:

- spacing
- alignment
- typography
- responsive behavior
- empty states
- loading states
- error states
- interaction states
